## pr-review-pre-cue

**Status:** default (scoped). **Default:** pr-review-toolkit pre-cue (pr-test-analyzer and silent-failure-hunter): locally in J8; its run in GitHub is retired (2026-10-10)

- **Route:** Runs before a landing cue; findings at confidence 80 or above go to the lane. Available now (the 2026-10-10 record, What remains): local Claude reads (trading-cc's pr-review-toolkit reads) and GPT reads (the command center's and the co-op's), all on the host; Codex's GitHub review, which the retirement does not affect; and GitHub's required `verdict-review-gate`, which enforces the verdict. Not available yet: the local Claude review worker (`tools/claude-review-worker`, #953, open), a candidate until it lands
- **Alternatives, ranked:** 1. Native `/code-review` at max effort (paired same-delta run owed, J7 class D)
- **Rejected:** Ultrareview as an automated default (user-triggered and billed; the owner's option for high-stakes PRs)
- **Evidence:** Measured: at or above 80, defects both designated reads missed on #892 (9), #894 (6), #895 (7), #896 (3) and trading #11 (2); $3.3-5.5 per run (J8 defects record)
- **Notes:** Ultrareview from a script runs as `claude ultrareview <PR#> --json`; `claude -p '/code-review ultra'` exits without findings. The run in GitHub (`claude-pr-toolkit-review.yml`, through #909) was retired on 2026-10-10 with the other Claude workflows, and the toolkit read never ran there (docs/decisions/2026-10-10-retire-in-github-claude-review.md; see github-action). A PR's description is published from a file and read back before the PR is reported or cued: write the body to a temporary file outside the repository, pass it to `gh pr create` or `gh pr edit` with `--body-file` (no shell interpolation), then compare `gh pr view <pr> --json body` with the file. Measured on 2026-10-11 against the description of #991 (restored afterwards): updates of 262,145, 262,199 (65,579 code points) and 1,048,577 UTF-8 bytes each got HTTP 200, and a GET read back the old description; an update of 262,144 bytes was stored. The catalog-freshness propose step does both (.github/workflows/catalog-freshness.yml). Source of the practice: fcakyon/claude-codex-settings@216ec221fb9899dfaa5371413583b9e08ca89085:plugins/github-dev/skills/create-pr/SKILL.md:35,40 (gap ledger B2-0004, 2026-10-15).
- **Supersedes:** M42; M31
- **Overturn when:** The paired same-delta run shows `/code-review max` matching or beating the toolkit on confirmed findings at equal quality.
