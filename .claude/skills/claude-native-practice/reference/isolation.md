Client 2.1.295, checked 2026-10-09. Index: [slots.md](slots.md).

## sandbox

**Status:** trial. **Default:** Hardened native Bash sandbox, delivered through `claude --settings` or managed settings

- **Route:** `enabled`, `allowUnsandboxedCommands: false`, `failIfUnavailable: true`, `autoAllowBashIfSandboxed: false`, `network.strictAllowlist` with an explicit `network.allowedDomains` in the same user-scope or `--settings` file, credential deny entries; owner opt-in after M1's arms pass. Under `strictAllowlist` the allowlist is `allowedDomains` plus the domains of `WebFetch(domain:...)` allow rules, and every other host is denied without a prompt, so a strict arm with no list denies every sandboxed network call (sandboxing.md:575, fetched 2026-10-15). The list is frozen through M1 before rollout: its strict arm allowed `api.github.com` and `github.com`, and its round 2 added `127.0.0.1` and `localhost`, which reach host loopback services only through the sandbox proxy (evidence/artifacts/claude-native-practice-20261009/probes-20261009.json:382-383, :393, :399). Host change proposed to the command center as a host diff, not applied (gap ledger C1-0022, 2026-10-15)
- **Alternatives, ranked:** 1. anthropics/sandbox-runtime around the whole process; 2. Dev container or VM for bypass sessions (the docs' guidance; candidate, not adopted without measurement)
- **Rejected:** dagger/container-use; Prompt-contract isolation; Sandbox without filesystem isolation
- **Evidence:** sandboxing.md; sandbox-environments.md (bypass sessions belong in a container, VM or the sandbox runtime)
- **Notes:** The native sandbox bounds shell commands only; file tools, MCP servers, hooks and the status line stay outside it. Bypass is not reopened.
- **Supersedes:** M1 refined
- **Overturn when:** M1's arms pass on this host and the owner opts in, or a worker is seen taking a harmful action.

## worktrees

**Status:** default (scoped). **Default:** Coordinator-created worktree at the exact base (`git worktree add --no-track <path> -b <branch> <base>`), with the session started in it

- **Route:** The native isolation checks apply to `--worktree` and EnterWorktree sessions. Background sessions (`claude --bg` or agent view) reach them through `worktree.bgIsolation`, default `"worktree"`: Edit and Write in the main checkout are blocked until the session calls EnterWorktree, so it moves into a worktree under `.claude/worktrees/` before editing (agent-view.md:551; settings-reference.md:5275-5281; fetched 2026-10-15). For a plain foreground launch the main-checkout protection is the builder's prompt contract. A lane parks unfinished work as a WIP commit on its own branch, not with `git stash`: every worktree of the repository shares one `refs/stash` (git-worktree.adoc:298-302, git v2.53.0)
- **Alternatives, ranked:** 1. A WorktreeCreate hook that creates each worktree at its exact base; 2. Pre-create at the exact base under `.claude/worktrees/<name>`, then `claude --worktree <name>`; 3. Native `--worktree` with `worktree.baseRef: head`; 4. max-sixty/worktrunk
- **Rejected:** `isolation: worktree` in builder frontmatter (rewrote core.hooksPath on 2026-09-25)
- **Evidence:** worktrees.md (checks apply to --worktree and EnterWorktree sessions); 2026-09-27 settings record (hooksPath incident)
- **Notes:** Adjudicated: the current practice stands (refuter pending at writing). Owed: the M49 probe on 2.1.295 for the WorktreeCreate and pre-create paths. Background isolation (gap ledger B4-0003, 2026-10-15): a session moved to the background with the left-arrow key or `/background` keeps editing in place whatever the key says, and Claude also skips the worktree when the session or the edited file is already in a linked worktree, when the directory is not a git repository and no WorktreeCreate hook is set, and for a write outside the working directory (agent-view.md:553-559). The key blocks only Edit and Write: a shell write such as `cp` or a redirect is not refused (worktrees.md:95). Subagents of a background session no longer bypass the guard since 2.1.154 (anthropics/claude-code@94506ff0 CHANGELOG.md:5037, v2.1.300), and from 2.1.288 a blocked subagent is told how to proceed (Piebald-AI/claude-code-system-prompts@0b7ce11f CHANGELOG.md:216; the reminder text is in the 2.1.300 binary). Neither this host's user settings nor the repository's settings set `worktree.bgIsolation`, and the host has no managed settings (read 2026-10-15), so the default holds. Measured context, 2026-10-15: d4 ran as a `claude --resume ... --bg` copy (33888fe1) launched from the main checkout at 07:12:15Z. Its transcript to 10:51Z has no EnterWorktree call, every record's cwd is the main checkout, and its five Edit and Write calls all target files under ~/.local/state/native-agent-stack/coordination, outside the working directory, so the session needed no worktree; `git worktree list` (561 entries, 11:41Z) has none under .claude/worktrees. Whether the key blocks a main-checkout edit was not measured. Stash (gap ledger B2-0003, 2026-10-15): `refs/stash` is one stack in the shared .git, so `git stash pop` in one lane can apply and drop another lane's entry. Measured 2026-10-15 on git 2.53.0 in a scratch repository: a stash pushed in one worktree was listed in a sibling, and `git stash pop` there applied it and emptied the stack (tests/test_native_practice_ledger_isolation.py repeats this). The 2026-10-11 record parked a held correction with native Git stash (docs/decisions/2026-10-11-final-stack-review-corrections.md:559); the shared stack proves no loss there and does not make an explicitly named stash entry unsafe, so the WIP commit is the default, not a ban.
- **Supersedes:** M49 refined
- **Overturn when:** The M49 probe passes for a native path: concurrent builders from different exact bases, the four checks applied and core.hooksPath unchanged.
