## Method and evidence boundaries

1. Match every candidate to the immutable inventory and supplied GitHub-facts record. Prefer its frozen latest-release tag/commit; a monorepo release tag is not assumed to be the package version. E2B, OpenLIT and Temporal expose important component/distribution distinctions in their rows.
2. Read existing upstream mirrors at the exact commit with `GIT_NO_LAZY_FETCH=1` and `GIT_OPTIONAL_LOCKS=0`. When the object/file was absent, read anonymous GitHub raw/tree/release endpoints at that pin. Do not fetch into, mutate, clone or execute candidate repositories. Mirrors may contain a different pin; their current HEAD is not substituted.
3. Read docs and source only, extracting numbered ranges and checking the needed mechanism. Context-mode was used for bounded source/JSON processing. Release-asset metadata was read without downloading binaries. Dated official documentation supplies package-manager inverses or vendor pages where the pinned repository points there.
4. Give each requirement its own PASS/FAIL/UNKNOWN and source. Describe exact interfaces, defaults and limitations. Installation commands are quoted as documented at the source pin; floating commands are not represented as a version-bound installation. INCOMPLETE retains unbound distributions, package/SDK tuples, architecture dependencies or inverses.
5. Separate role choice from capability. Every suited-role value and family-profile mapping is **CANDIDATE / PROPOSAL**, routed to the [layer-resolution protocol](../../../docs/decisions/2026-10-11-layer-resolution-protocol.md). No assignment is a convergence result. Fenced trading, judge and review sessions are never an allowed activation or collection target.
6. Record actual default ports, shared config/state, unit names, PATH entries, telemetry destinations and optional MCP/plugin surfaces where read. The cross-distribution WSL2 port namespace is a task constraint; no private host port inventory or existing client configuration was inspected.
7. Screen only the named component mode. Optional skills, MCP integrations, coding hooks, model-generation features or full auto-instrumentation installers are identified where relevant but do not inherit a CLI/server-only PASS or zero-token estimate. Such modes require their own scoped contract before activation.

Official package-manager inverse references, read 2026-10-15: [npm uninstall v11](https://docs.npmjs.com/cli/v11/commands/npm-uninstall), [pip uninstall](https://pip.pypa.io/en/stable/cli/pip_uninstall/) and [Homebrew manpage](https://docs.brew.sh/Manpage). Package removal does not imply removal of user data, cloud resources, hooks, services or transitive dependencies.

## Start-up context and visibility

All start-up costs are **CANDIDATE ESTIMATE**, not measurements. For a named external CLI/daemon/SDK-only profile that registers no model-facing instructions, skills, hooks or MCP schemas, the counted injected-text set is empty: 0 UTF-8 bytes, `ceil(bytes / 4) = 0`. This is an incremental host-injection estimate, not the model's baseline prompt or the context used by the application invoking that component. Optional integrations and model/chat templates are outside that narrow estimate and cannot inherit it.

Claude HUD is the explicit nonempty text case. At `jarrodwatts/claude-hud@ad322b8d9016816a1858334ba57a085512110e83`, `commands/setup.md:2` has a 39-byte description value (10 estimated tokens), and `commands/configure.md:2` has a 118-byte value (30). Strip the `description:` prefix and surrounding whitespace; count UTF-8 bytes; round each value up at four bytes/token. The known description payload is **157 bytes / ESTIMATE 40 tokens**. The total remains UNKNOWN because the matching host's generated command names/discovery wrappers are not counted. On-demand command bodies are not automatic startup text. Disabling its display does not unload plugin metadata. Not-served families install nothing and therefore have an empty counted set.

Each observation row records upstream visibility primitives and separate per-lane, per-unit and per-worker results. Generic resource labels, GPU IDs, inference slots or process IDs are not silently renamed into a lane/work-unit/worker schema. AgentsView documents metadata/subagent-link identifiers; Claude HUD documents active-agent display. These are source capabilities, not a designed central view or measured cross-lane joins.
