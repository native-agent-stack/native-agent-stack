## Method and boundaries

The layer-resolution protocol, converged-candidates-only decision, angle-records decision and angle schema were read at repository base 8053f14e7. The three foundation rows and their final-stack rows are reopened; none is FINAL. The retained winners/alternatives and September 29 survivors were consumed through the deterministic inventory/final-stack inputs. The bounded delta is their A1 screen, not a new landscape sweep. Existing quality, recovery, language coverage, provider-accounting and comparative gaps remain open. The boolean a1_screened angle field is not written by this lane.

Requirements are decomposed from foundation.json: useful context/recoverable originals/separate accounting for token-efficiency; scoped durable records, native-client access, inspectable capture, deletion and recovery for memory; exact source/references and task-scoped retrieval for navigation. Every row also records maintenance, Linux/WSL2 x86_64, macOS arm64, headless use, profile/project scope and the family's route. A declared portable-runtime route is identified as a source compatibility inference, not a native execution result. A Linux claim applies to WSL2's Linux environment; it is not evidence for native Windows.

Only missing required capability (including an actual entitlement/terms conflict) and abandonment are hard disqualifiers. Missing or ambiguous source remains UNKNOWN/INCOMPLETE. An inactive default branch and HTTP 404 are not proof of abandonment. License information never changes a verdict. API-backed memory or compression features are not entitled by a source read; no subscription credential reuse is approved by this record.

The original layer capability contract is retained: a Claude-local or separate-runtime memory product can fail cross-native-client access while remaining useful in its own local slot. That is not a decision to remove an existing native feature.

The suited-role lists are **proposals**, derived from the cited candidate capabilities. They are not adopted practice, a role-wide mandate, or an A1 pass/fail criterion. The coordination correction receipt listed below was applied. Context-lead, halt-aware/session-leverage, lane-charter and horizon designs are not promoted here. Fenced trading, judge and review sessions remain excluded; an ordinary reviewer proposal does not include a fenced review.

No candidate installation, candidate CLI/server launch, clone-and-run, model invocation or keyed candidate/vendor API request was performed. Source retrieval was anonymous; authorized GitHub publication is separate. Source was read with git show/ls-tree from existing upstream mirrors when the object existed, otherwise anonymous GitHub raw/REST requests. Candidate source was parsed as data, never imported or executed. Existing research-harness tools performed these static reads. No credential files were read.

The selected recipe matters: a documented direct CLI or MCP-only route is not permission to run an auto-discovering installer, add global hooks, rewrite model routes, load all skills or adopt a second memory owner. Tables describe those optional conflicts explicitly. Family configuration uses the vendor's entry point plus the native host's documented scope; commands are reviewable recipes, not executed instructions. Floating upstream selectors must resolve to the screened pin before installation.

## Startup estimates

Every numeric value is **ESTIMATE**, using ceil(UTF-8 bytes / 4), not a measured provider tokenizer or a session-start measurement. Counted source ranges are present in each JSON row. Full descriptors, fixed instruction text, partial literals and empty startup payloads are distinguished:

- Direct CLI-only routes add an empty startup payload: 0 bytes / 0 tokens. Their later command output, packed file or format example still costs task context. Optional init/plugin/hooks are outside that zero.
- Headroom's three default tool objects were reconstructed from Python AST literals and constant f-string substitutions without executing source. Their compact JSON objects sum to 1,246 bytes: 312 estimated tokens, before client envelopes/deferral. Optional headroom_read is excluded by its default-off flag.
- Context Mode's known literal text in 11 description starts totals 6,740 UTF-8 bytes after decoding escapes and excluding the two runtime interpolation expressions: 1,685 estimated tokens for that fixed component. Runtime bunNote/langList values, remaining concatenated/dynamic parts, parameter schemas and client rendering are not counted as zero. The selected MCP-only route adds no routing hook or skill. Full plugin cost is different.
- Fixed files and server instructions use their exact string/file bytes where available. Generated memory indexes, repository-specific text, runtime tool catalogs and client-selected tool tiers remain variable. A partial component is never represented as a complete startup total.
- Deferred tool loading can keep full schemas out of the initial model context. An eager descriptor component is not an assertion that the native client injects it at startup. Research tool-selection prompts may add context of their own.

NativeHorizonNY's actual startup receipt supersedes these estimates. Artifact reductions, native provider input/output/cache fields, billed cost and counterfactual savings remain separate; no numbers are summed across overlapping compressors.
