## Method

The layer-resolution protocol, converged-candidates rule, angle final-check decision and `a1_screened` schema field were read first. The bounded delta is the assigned candidate screen. Source reads prefer registered `~/code/upstream` mirrors, with `GIT_NO_LAZY_FETCH=1` and `GIT_OPTIONAL_LOCKS=0`. Missing objects are read from public GitHub URLs at the exact commit; archives are read in memory, never extracted or executed. Pins use the supplied current head snapshot for skill packs, and the supplied current release for executable surfaces/frameworks where suitable. ECC uses the supplied head `76aaa77d...`. Older retained execution pins are not presented as execution at these new pins.

Every requirement is PASS, FAIL or UNKNOWN. A screen FAIL needs a missing required capability (including a terms/entitlement conflict) or abandonment. Missing evidence yields INCOMPLETE with a bounded next source check. Licence is recorded only as a dated compliance note. Popularity fields were discarded before judgment. A PASS supports only its stated component and host route; no server bundled or listed by a candidate inherits a pass.

No installation, candidate CLI invocation, provider/model request, credential read, or secret inspection occurred. Repository validation and receipt registration are local evidence tooling, not candidate execution. GitHub publication is the separately requested output action.

## Startup cost

All token counts are **ESTIMATE**, using `ceil(UTF-8 bytes / 4)`. Skill estimates count the pinned name and description strings and cite their frontmatter line ranges. Multiline descriptions are normalized with spaces. Full skill bodies are excluded until selected, except a body explicitly injected by a startup hook. Hook text is counted from its pinned literal/template and referenced input file, without executing the hook. Dynamic project/memory text and MCP schemas are reported separately as unknown where source cannot fix their bytes. A source-code byte count is never passed off as injected prompt text.

Claude's documentation, read 2026-10-15, states that manual-only skills omit descriptions and that a skill-listing budget can drop descriptions. Reported metadata totals therefore precede client rendering, budget truncation and wrappers. They are source payload estimates, not measured session token counts. Optional/preloaded worker skills can load full bodies; that separate mode is not included unless a row says so. CLI-only tools with no startup registration add an empty payload, estimated at zero; their later outputs and downstream schemas still cost context when invoked.

NativeHorizonNY must retain actual session-start measurements and discovery/configuration receipts at installation. Those measurements supersede these estimates without silently rewriting the source-review evidence.
