## Native capture and deterministic masking

The published [capture.py](capture.py) uses Python's documented [subprocess.run](https://docs.python.org/3.14/library/subprocess.html#subprocess.run) with binary file handles for stdout/stderr; it does not decode, combine, truncate or fabricate child output. It constructs an explicit environment rather than inheriting credentials. No credential files or directories are read. The [mask.py](mask.py) adapter uses documented [bytes.replace](https://docs.python.org/3.14/library/stdtypes.html#bytes.replace) and regular-expression substitution, read 2026-10-16. These are local capture/publication adapters, not a new adopted runtime. The search-first and modern-python skills informed the bounded reuse check; no external Python dependency was added.

The existing `scripts/host_receipts.py:733-748` captures decoded, combined text, so it is not used as the raw byte recorder. Its native `register_file` function registers the public evidence files. The published masker applies only these declared transformations:

1. Private scratch/repository/home prefixes become marked `<SCRATCH>`, `<REPOSITORY>` and `<HOME>` placeholders, longest match first.
2. Digest-shaped hexadecimal tokens of 16–128 characters become `<MASKED_DIGEST>`, except an explicit allowlist of **public** source commits/tag objects. This prevents SBOM file fingerprints or raw hash prefixes from escaping.
   UUID-shaped tokens also become `<MASKED_UUID>` under the existing publication policy at `scripts/validate.py:40` in the base. This includes public image-asset names in the upstream Syft README; it does not change any capability or runtime observation.
3. All remaining stream bytes, ordering, diagnostics, empty output and line endings are preserved. Receipt metadata retains the native return code and timing. Raw-stream hashes are verified privately and replaced by hashes of the **published** streams.

The masked SBOM is an evidence derivative, not an operational SBOM suitable for downstream matching. No hash of unpublished raw bytes is published. Exact commands and raw streams stay private, cited by capture **name** only. The co-op receives the private raw/map locations for byte-for-byte reproduction. The [ten custody tests](test_capture_mask.py) cover binary and failed output, empty streams, overlapping path prefixes, public/private digests, UUID-shaped identifiers, idempotence, reproducibility, tamper rejection and overwrite refusal; [their native test output](captures/custody-tests-final/stderr.txt) is labelled synthetic test evidence, not candidate E2E.

The first repository validation rejected those public UUID-shaped image names. The additional masking case has a [native fail-before capture](captures/mask-uuid-regression-before/receipt.json) (one test, exit 1) against [the retained earlier masker](mask-before-uuid.py.txt), followed by [all ten tests passing](captures/custody-tests-final/receipt.json). The candidate runs and their private native bytes were not repeated or edited. This corrects the publication adapter, with the upstream byte/regular-expression APIs and the pinned repository rule as its sources.
