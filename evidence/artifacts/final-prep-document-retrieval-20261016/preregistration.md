## Native scoring harnesses and metrics

Use the maintained [ViDoRe pipeline evaluator at `a70f23af8bb3b33efe8a4a6c6c15a6e2d978035e`](https://github.com/illuin-tech/vidore-benchmark/blob/a70f23af8bb3b33efe8a4a6c6c15a6e2d978035e/README.md#L175). Its supported `BasePipeline.index/search` interface is the adapter boundary for native candidate outputs; its `evaluate_retrieval` and `aggregate_results` own scoring. The maintainer moved single-model evaluation to MTEB but continues to maintain this pipeline route. No local replacement evaluator is proposed.

The **PRIMARY endpoint is passage-level retrieval**, as approved in the same CC input ruling: conventional **recall@1, @5, @10, @20 and @100**, plus **MRR@100**, against qrels aligned by text span. Pass the corresponding `pytrec_eval` recall metrics to the native evaluator; return at most 100 ranked canonical passage IDs and use `recip_rank` on that truncation for MRR@100. Both qrel scores count as relevant. The source dataset's page/bounding-box qrels are inputs to the pre-run passage judgment seal, not silently relabeled passage truth. Report query-level values and macro means, native coverage counts, failures and empty results. Do not use QMD's older nonstandard precision denominator as conventional precision. No significance claim or independent-sample multiplication is made from deterministic repetitions.

Every arm's output, flat or page-aware, maps to the **same canonical passages** under the method below. Converter/OCR arms feed the same fixed retrieval backend in paired BM25/hybrid conditions, so a flat-text converter is assessed on retrievable passage content. Native retrieval systems keep their supported ranking, mapped to the same passage IDs. A separate retrieval-only control may use the same sealed truth corpus, clearly labeled as bypassing ingestion. QMD's predeclared ablation is lexical BM25 versus supported dense+sparse hybrid with the same documents, queries, chunk policy and local model; expansion/reranking must be disabled identically unless separately sealed. Exact native hybrid flags/API and fusion parameters remain a pre-seal input, not an implementation choice after seeing scores. A system without a supported ablation records that limitation rather than receiving an invented interface.

**Structure fidelity is SECONDARY, reported only for page-aware arms on the four difficult-layout strata, and never enters the decision rule.** Use [OmniDocBench at `f133a71e9e91c3621c7ce8994200a7b394a06eb3`](https://github.com/opendatalab/OmniDocBench/blob/f133a71e9e91c3621c7ce8994200a7b394a06eb3/README.md#L929), its supported `pdf_validation.py --config ...` path and `end2end`/`quick_match` configuration. Report native table TEDS, reading-order edit distance and supported layout/reference metrics separately, stratified by the frozen page attributes. Flat Markdown receives no structure penalty. Any text edit-distance diagnostic remains separately labeled and cannot substitute for the primary retrieval endpoint. A common image-to-PDF conversion, if needed, uses upstream `tools/image_to_pdf.py` settings frozen once for all applicable arms. That raster wrapper does not turn an OCR case into a born-digital PDF test for Poppler.

## Passage alignment method and tolerance — fixed before execution

The born-digital subset supplies exact text truth. Before any candidate output, retain a `passages.jsonl` with document identity, original text-span offsets, canonical text and a stable passage ID, plus `passage-qrels.jsonl` mapping the source judgments to those spans. Two independent native PDF text readers must agree after the normalization below; a witness resolves disagreement against the PDF before the seal. No candidate output or model-generated answer is used to author truth. Reader pins, the resulting passage bytes and source-qrel-to-span adjudications remain required artifacts.

1. Normalize canonical and candidate text with Unicode NFKC, remove U+00AD soft hyphens, and collapse Unicode whitespace to one space. Preserve case, numbers, punctuation and ordinary hyphens. Keep the original-to-normalized offset maps. No semantic rewrite or spelling repair is permitted.
2. Define canonical passages before queries are scored: preserve source paragraphs, split paragraphs longer than 512 normalized Unicode code points at the last whitespace at or before that limit, with no overlap; retain short final spans. The seal binds every passage's exact text and offsets. Query relevance is assigned by witnessed source text spans, not by a candidate's page layout.
3. Align canonical passages against each arm's own normalized extracted text using upstream [RapidFuzz `partial_ratio_alignment`, source `377d0c0ace35bbb4683180ebf110414dfff11abb`, `src/rapidfuzz/fuzz_py.py:260`](https://github.com/rapidfuzz/RapidFuzz/blob/377d0c0ace35bbb4683180ebf110414dfff11abb/src/rapidfuzz/fuzz_py.py#L260). The predeclared tolerance is **score >= 98.0** and normalized Levenshtein distance **<= 0.02 of the longer span**, with **all digit sequences identical**. Both conditions must hold. For canonical passages shorter than 32 code points, require exact normalized equality. The implementation may only adapt the upstream alignment API; it must not replace the scoring harness.
4. Accept a mapping only when the qualifying source span is unique within its document. Repeated/ambiguous passages and unmatched text retain explicit dispositions; no best-looking qrel association is selected after retrieval. Resolve unavoidable reference ambiguities in the common passage seal before any arm runs, without seeing arm output. An arm's later alignment failure is an observed missing passage.
5. Preserve candidate text in retrieval inputs. Alignment assigns an ID and does **not** substitute canonical words, repair OCR, inject answers or pass qrels to the candidate. A native result covering multiple passages is expanded in native result order then source-span order; collapse duplicate passage IDs at their earliest rank and truncate at 100. Unmatched returned material remains in the retained result log and consumes its returned position, so it cannot disappear to improve the score. Freeze this adapter behavior and its upstream-harness check before execution.

Primary decisions use passage recall/MRR and reported cost per query. No bounding-box, page-structure, TEDS or reading-order score enters selection. A flat arm therefore has the same content/retrieval criterion as a page-aware arm. Material quality/cost disagreement goes to both families rather than to an unregistered composite score. The numeric alignment tolerance and its ambiguity policy require witness review with the canonical truth seal; they cannot be tuned after results.
